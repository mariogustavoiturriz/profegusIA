La Regla de Oro: El Restaurante

Para entender tu código, imaginate que tu programa es un restaurante:

  • La Cocina (Backend): Es la función consultar_ia. El chef trabaja a puertas cerradas, se conecta a internet y cocina la respuesta. Nunca sale a hablar con el cliente (no usa print).
  • El Salón (Frontend): Es el bucle while True. Es el mozo que atiende al usuario, anota los pedidos y habla con él.
  • La Libreta (El Historial): Es la memoria. El mozo anota TODO ahí para no olvidarse de nada.
CAJA AZUL: EL MOTOR (No se toca)
Lo que está en estas cajas es estructural. Solo tenés que copiarlo y ubicarlo en el lugar correcto.
CAJA ROJA: TU CREATIVIDAD (Vos completás)
Acá completás vos. Son tus datos, tus reglas y tus variables.

¿Cómo funciona la memoria? (El Historial)

La lista historial es, literalmente, un chat interno. Cada mensaje tiene un "quién" (role) y un "qué dijo" (content).

CÓMO SE VE LA LIBRETA POR DENTRO
A medida que avanza el programa, la lista va creciendo así:
Posición 0 (System){"role": "system", "content": "Sos un guía de Ushuaia..."}
Posición 1 (User){"role": "user", "content": "Hola, ¿quién sos?"}
Posición 2 (Assistant){"role": "assistant", "content": "Soy Marcos, guía del fin del mundo."}
Posición 3 (User){"role": "user", "content": "¿Qué lugares recomendás?"}
¡Si no guardamos el mensaje del usuario y la respuesta de la IA en cada vuelta, el bot se olvida de lo que acabamos de hablar!

PARTE 2: El Motor (Adentro del while True)

El bucle while True es un ciclo infinito. En cada vuelta se frena en el input() y, dependiendo de lo que escriba el usuario, toma uno de tres caminos (las Puertas).

⚠️ Error frecuente: el /guardar tiene que ir PRIMERO El comando /guardar debe estar antes de que el programa llame a la IA. Si lo ponés al final del bucle, primero manda el texto "/guardar" a la API y gasta tokens innecesarios. Fijate en el orden de las Puertas abajo.
Las 3 Puertas del Frontend — en el orden correcto
while True: consulta = input("Vos: ") # EL PROGRAMA SE FRENA ACÁ # ───────────────────────────────────────────────────────── # PUERTA 1: EL USUARIO SE QUIERE IR # Si escribe "salir", nos despedimos y rompemos el ciclo. if consulta.lower() == "salir": print("¡Chau!") break # ───────────────────────────────────────────────────────── # PUERTA 2: EL USUARIO QUIERE GUARDAR EL LOG # Va ANTES de llamar a la IA para no gastar tokens innecesarios. # El continue al final es OBLIGATORIO: sin él, el código de abajo # igual se ejecuta y le manda "/guardar" a la IA como si fuera un mensaje. if consulta.lower() == "/guardar": with open("conversacion.txt", "w", encoding="utf-8") as archivo: for linea in historial: archivo.write(f"{linea['role']}: {linea['content']}\n\n") print("¡Archivo guardado!") continue # ← OBLIGATORIO: vuelve arriba sin pasar por la Puerta 3 # ───────────────────────────────────────────────────────── # PUERTA 3: EL USUARIO QUIERE CHARLAR (El camino normal) # Solo llega acá si NO escribió "salir" ni "/guardar". # A) Anotamos lo que dijo el usuario en la libreta historial.append({"role": "user", "content": consulta}) # B) Le mandamos la libreta al Backend para que cocine la respuesta respuesta_ia = consultar_ia(historial, temp) # C) Imprimimos la respuesta en pantalla print(f"IA: {respuesta_ia}") # D) Anotamos lo que respondió la IA para que no se olvide historial.append({"role": "assistant", "content": respuesta_ia})

📝 Cuestionario de Fijación

Leé cada pregunta y seleccioná la respuesta correcta. Al final apretá "Corregir".

🔄 Ordená el Flujo del Chat

Pensá en la Puerta 3 (cuando el usuario quiere charlar). Ordená estos pasos usando los botones.

El programa imprime la respuesta en la pantalla (print).
El usuario escribe su consulta en el input.
El programa anota la respuesta de la IA en la libreta (append assistant).
El programa anota lo que dijo el usuario en la libreta (append user).
El programa le manda la libreta completa al Chef (llama a consultar_ia).

¿Dónde va el diccionario jugador?
Va entre las constantes y el historial — afuera del bucle, igual que el historial:
# Después de las constantes (URL, headers) y la función consultar_ia jugador = { "nombre": "Viajero", "hp": 100, # HP = Hit Points = puntos de vida "inventario": [], "ubicacion": "punto de partida" } historial = [] # La libreta, igual que siempre historial.append({"role": "system", "content": game_master})
¿Cómo se inyecta el estado en la Puerta 3?
En lugar de mandar solo lo que escribió el usuario, mandamos el estado actual del jugador también. Así el narrador siempre sabe cómo está el personaje:
# En la Puerta 3, en lugar de: historial.append({"role": "user", "content": consulta}) # Usamos esto (el estado viaja junto con la acción del jugador): mensaje_turno = f"""[Estado: HP={jugador['hp']}, inventario={jugador['inventario']}] Acción: {consulta}""" historial.append({"role": "user", "content": mensaje_turno})
💡 Lo único que cambia de verdad El System Prompt ya no define un asistente que responde preguntas. Ahora define un narrador que guía una historia: describe el mundo, interpreta las acciones del jugador y al final de cada respuesta siempre ofrece 3 opciones (A, B, C) para que el jugador elija.
