2 CONCEPTO NUEVO ★ TRAMO 3 — LA IA COMO EXTRACTOR DE DATOS

Hasta ahora la IA siempre devolvió texto libre. Hoy aprendemos a pedirle que devuelva texto + datos estructurados en formato JSON al mismo tiempo. Esto se llama output schema — definir de antemano qué forma tiene que tener la respuesta.

¿Por qué necesitamos esto en el juego?

Cuando la IA narra "el dragón te quita 30 HP y encontraste una llave", el diccionario jugador no cambia solo. Alguien tiene que actualizar el HP y el inventario.

En grupos de 2 eso lo hace el jugador a mano con /hp -30 y /tomar llave. En grupos de 3 se lo pedimos a la IA directamente: que incluya un bloque JSON en cada respuesta con los cambios, y el código lo parsea.

🔤 Respuesta normal (grupos de 2)

"El dragón te ataca con sus garras. Perdés 30 HP y caés al suelo. Encontrás una llave entre los escombros. A) Huir por el pasillo norte B) Usar la llave en la puerta C) Atacar al dragón"

Solo texto. El jugador actualiza el estado a mano.

📦 Respuesta con JSON (grupos de 3)

"El dragón te ataca con sus garras. Perdés 30 HP y caés al suelo. Encontrás una llave entre los escombros. A) Huir B) Usar la llave C) Atacar ```json {"hp_delta": -30, "agregar": ["llave"], "quitar": []} ```"

Texto + JSON. El código extrae el JSON y actualiza el diccionario solo.

¿Cómo se instruye al narrador?

Se agrega una regla en el System Prompt. El narrador tiene que incluir ese bloque JSON siempre, aunque no haya cambios:

# En el system prompt del narrador (grupos de 3): """ ...reglas del narrador... Al final de CADA respuesta incluí un bloque JSON con los cambios de estado: ```json {"hp_delta": N, "agregar": ["objeto"], "quitar": ["objeto"]} ``` hp_delta es la variación de HP (negativo si pierde, 0 si no cambia). Si no hay cambios usá: {"hp_delta": 0, "agregar": [], "quitar": []} """

¿Cómo lo parsea el código?

Después de recibir la respuesta del narrador, el código busca el bloque JSON, lo extrae y lo aplica al diccionario:

import json, re # Extraer el bloque JSON de la respuesta del narrador match = re.search(r'```json\s*(.*?)\s*```', narracion, re.DOTALL) if match: try: cambios = json.loads(match.group(1)) jugador["hp"] = max(0, jugador["hp"] + cambios.get("hp_delta", 0)) for obj in cambios.get("agregar", []): jugador["inventario"].append(obj) for obj in cambios.get("quitar", []): if obj in jugador["inventario"]: jugador["inventario"].remove(obj) # Mostrar solo el texto, sin el bloque JSON texto_limpio = re.sub(r'```json.*?```', '', narracion, flags=re.DOTALL).strip() print(f"\n🌲 {texto_limpio}\n") except: print(f"\n🌲 {narracion}\n") # si el JSON falló, mostrar todo igual else: print(f"\n🌲 {narracion}\n")
⚠️ La IA no siempre devuelve JSON válido A veces el modelo se olvida del bloque JSON, lo formatea mal o lo incluye dentro del texto. Por eso el try/except es obligatorio: si el parseo falla, el juego sigue igual — solo no se actualiza el estado automáticamente. Eso es exactamente lo que veremos en C15: validación de outputs.

3 LOS GRUPOS Y LOS NIVELES

Grupos de 2

🗺️ Estado + Comandos manuales

La IA devuelve solo texto. El jugador actualiza el estado con comandos.

  • Diccionario con HP, inventario, ubicación
  • /estado /tomar /soltar /hp ±n /guardar
  • System Prompt: narrador + 3 opciones por turno
  • Sin JSON, sin parseo
Grupos de 3

🧠 Estado + JSON output schema

La IA devuelve texto + JSON. El código parsea el JSON y actualiza el diccionario automáticamente.

  • Mismo diccionario que grupos de 2
  • Sin /tomar /soltar /hp — los reemplaza el parseo
  • System Prompt: narrador + 3 opciones + bloque JSON obligatorio
  • Concepto nuevo: json.loads(), re.search(), try/except para validar
