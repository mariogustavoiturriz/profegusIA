1 DÓNDE ESTÁ LA IA REALMENTE

La confusión más común es creer que la IA "está" en tu Colab. No está. Tu programa tiene dos lados, y viven en computadoras distintas:

💻

FRONTEND (cliente)

Tu Colab · tu código

  • Pide la acción al jugador
  • Guarda el historial
  • Arma el pedido (payload)
  • Muestra la respuesta
▶ PEDIDO
(JSON)
internet
◀ RESPUESTA
(JSON)
🖥️

BACKEND (servidor de Groq)

Máquinas de Groq, en otro país

  • Verifica tu API Key
  • Corre el modelo gpt-oss-120b
  • Genera la respuesta
  • La devuelve en JSON
Tres consecuencias de esto
  • Sin internet no hay IA. El modelo no está en tu máquina: es demasiado grande para tu compu.
  • Necesitás una API Key. Es tu credencial para que el servidor te atienda.
  • El servidor no te recuerda. Cada pedido es independiente — por eso mandás el historial entero cada vez.

2 EL MODELO: openai/gpt-oss-120b

Ese nombre que copiaste sin pensar dice cuatro cosas:

openai — Quién lo desarrolló. Groq no fabrica el modelo: presta las máquinas donde corre.
gpt — El tipo de arquitectura con la que está construido, la misma familia de tecnología que usan casi todos los modelos de lenguaje actuales.
oss — Open source: sus pesos son abiertos y cualquiera puede descargarlo o servirlo. Por eso Groq puede ofrecerlo en su plataforma.
120b — 120 mil millones de parámetros: los números internos que el modelo ajustó durante su entrenamiento. Ahí está "lo que sabe".
🔄 Los modelos se dan de baja: esto pasó de verdad, hace unos días Hasta hace poco este taller usaba llama-3.3-70b-versatile. Groq anunció que deja de funcionar el 16 de agosto: después de esa fecha, cualquier programa que lo pida recibe un error. Por eso migramos a openai/gpt-oss-120b.

Esto es parte normal del oficio: los modelos se actualizan y se retiran, y quien programa con IA tiene que estar atento. La buena noticia es que el cambio fue una línea: como el resto del código no depende del modelo, se reemplaza el nombre y todo lo demás sigue igual. Cuando programás bien, cambiar de motor no te obliga a rehacer el auto.
⚠️ Qué hace un LLM (y qué NO hace) Un modelo de lenguaje predice el texto más probable, pedacito por pedacito. No busca en internet, no consulta una base de datos con la verdad, y no razona como una persona. Cuando le falta un dato, igual completa con algo verosímil: eso es una alucinación, y no es un error del programa — es cómo funciona.
Por eso el proyecto nuevo se llama Extractor y no "Adivinador" Vas a pedirle que saque datos que están escritos en el texto, y después vas a verificar que no haya inventado nada. Ese control es una de las partes que se evalúan.

3 JSON: EL IDIOMA DEL VIAJE

Tu Colab habla Python; el servidor no sabe Python. Para entenderse usan un formato neutro que entienden los dos: JSON. Todo lo que va y lo que viene tiene esta forma.

➡️ Lo que SALE de tu programa (el payload):

{ "model": "openai/gpt-oss-120b", <- qué modelo querés "temperature": 0.7, <- cuánto puede variar "messages": [ <- TODA la conversación {"role": "system", "content": "Sos el Narrador..."}, {"role": "user", "content": "abro la puerta"}, {"role": "assistant", "content": "La puerta cruje..."} ] }

⬅️ Lo que VUELVE del servidor:

{ "choices": [ <- lista de respuestas { "message": { "role": "assistant", "content": "Detrás de la puerta hay..." <- EL TEXTO } } ], "usage": {"total_tokens": 512} <- cuánto consumiste }
Por eso hay que "cavar" hasta el texto El servidor no devuelve la frase pelada: devuelve una caja con cajas adentro. Cada corchete abre una:

respuesta.json() → todo el JSON
["choices"] → la lista de respuestas
[0] → la primera
["message"] → el mensaje
["content"] → el texto que buscabas

4 DISECCIÓN DE TUS BLOQUES B2 Y B3

Estas son las líneas que venís escribiendo desde la Clase 6. Ahora las leemos entendiendo qué hace cada una:

# ===== B2 — LA CONFIGURACIÓN ===== API_KEY = "gsk_TU_CLAVE" # ^ Tu credencial. Identifica QUIÉN hace el pedido. No se comparte nunca. URL = "https://api.groq.com/openai/v1/chat/completions" # ^ La dirección exacta del backend: el "endpoint". # Es la puerta del servidor a la que le tocás el timbre. headers = {"Authorization": f"Bearer {API_KEY}", "Content-Type": "application/json"} # ^ Los datos del sobre: QUIÉN sos (Authorization) # y EN QUÉ IDIOMA le hablás (Content-Type: json). # ===== B3 — LA FUNCIÓN QUE HACE EL VIAJE ===== def consultar_ia(mensajes, nivel_creatividad): payload = {"model": "openai/gpt-oss-120b", "temperature": nivel_creatividad, "messages": mensajes} # ^ EL PEDIDO en JSON: qué modelo, cuánta variación, # y toda la conversación hasta ahora. try: respuesta = requests.post(URL, headers=headers, json=payload) # ^ EL VIAJE DE IDA. post = "te mando datos". # Acá tu programa se queda esperando la respuesta. return respuesta.json()["choices"][0]["message"]["content"] # ^ LA VUELTA, desarmada caja por caja hasta llegar al texto. except Exception as e: return f"Error: {e}" # ^ Si se cae internet o la clave está mal, avisa en vez de romperse.
Estas líneas son TODA la conexión con la inteligencia artificial El resto de tu RPG (el bucle, los comandos, el diccionario del jugador) es Python común. La IA entra por acá. Y en el proyecto nuevo este bloque se reusa casi sin tocar.

5 LOS ROLES Y EL CONTEXTO

Dentro de messages, cada mensaje tiene un rol. No son decorativos: le dicen al modelo cómo interpretar cada texto.

systemLa configuración: quién es y cómo se comporta. Tu guion del Narrador. Va en la posición 0, una sola vez.
userLo que escribe la persona. En tu RPG, la acción del jugador.
assistantLo que respondió la IA antes. Se guarda para que el modelo sepa qué dijo.
🧠 La memoria la ponés vos, no el servidor El servidor no guarda nada entre un pedido y el siguiente: se dice que la API es sin estado. La conversación existe solo porque tu programa la va acumulando en historial y la manda entera cada vez. Si no la mandás, el modelo arranca de cero como si nunca hubieran hablado.
🌡️ TemperaturaCuánto se arriesga el modelo. Va de 0 a 2, y si no la ponés, la API usa 1. Cerca de 0: predecible y estable → ideal para extraer datos. Alrededor de 1: variada y creativa → lo que usabas para narrar. Cerca de 2: tan aleatoria que la respuesta puede volverse incoherente.
🔢 TokensEl modelo parte el texto en pedacitos (tokens) y predice el siguiente. Hay un límite por pedido: si el historial crece mucho, no entra. Por eso a veces hay que recortarlo.
