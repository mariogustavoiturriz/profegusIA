Antes de empezar — Tu API Key

10 minutos · Se hace una sola vez

Sin la API Key nada funciona: es la credencial que te habilita a usar la IA. Si ya tenés una que funciona, salteá esto.

Paso 1 — Conseguir la clave
  1. Entrá a console.groq.com y creá una cuenta (es gratis).
  2. Buscá la sección API Keys.
  3. Tocá Create API Key, ponele un nombre cualquiera.
  4. Copiala y guardala en un archivo tuyo. Solo se muestra una vez.
Tenés un texto largo que empieza con gsk_ guardado en algún lado tuyo.
Importante: la clave es personal. No la compartas ni la subas a ningún lado público.

Sesión 1 — La función que habla con la IA

🎯 Meta: que tu programa mande un mensaje y reciba una respuesta
Paso 1 — Colab nuevo y la librería

Abrí un Colab nuevo (colab.research.google.com → Archivo → Nuevo notebook). En la primera celda escribí:

import requests

requests es la librería que le permite a Python mandar mensajes por internet. Es la que va a llevar tu mensaje hasta la IA.

Ejecutás la celda (Shift + Enter) y no pasa nada visible. Eso está bien: si no hay error, funcionó.
Paso 2 — Los datos de conexión

En una celda nueva, estas tres líneas. Reemplazá gsk_TU_CLAVE por tu clave real:

API_KEY = "gsk_TU_CLAVE" URL = "https://api.groq.com/openai/v1/chat/completions" headers = { "Authorization": f"Bearer {API_KEY}", "Content-Type": "application/json" }

Pensalo como una carta. Lo que le vas a preguntar a la IA es la carta. Estas tres líneas son el sobre: el cartero nunca abre la carta, le alcanza con leer el sobre para saber qué hacer con ella.

API_KEY — Tu credencial personal, la que sacaste al principio. Groq recibe millones de pedidos por día y necesita saber de qué cuenta viene cada uno.

URL — La dirección exacta adonde llega tu pedido. Se le dice endpoint: es la puerta del servidor a la que le tocás el timbre. Fijate que termina en /chat/completions, porque le estás pidiendo que complete una conversación. Groq tiene otras puertas para otras cosas (transcribir audio, por ejemplo).

headers — Los datos escritos en el sobre. Son dos, y responden dos preguntas distintas:

  • "Authorization" → ¿quién manda esto? Acá va tu clave. La palabra Bearer significa "portador" y es un estándar de la web: le avisa al servidor qué tipo de credencial viene a continuación, como decir "acá va una llave" antes de dar la llave. Lo vas a encontrar igual en casi cualquier API que uses en tu vida.
  • "Content-Type" → ¿en qué idioma está escrito? application/json le avisa que lo que mandás viene en formato JSON. Sin eso, el servidor recibe un montón de caracteres y no sabe si leerlos como JSON, como texto suelto o como un formulario.

La f-string del Authorization hace lo de siempre: reemplaza {API_KEY} por el contenido de la variable. Si tu clave es gsk_abc123, lo que realmente viaja es el texto Bearer gsk_abc123. Se hace así, y no escribiendo la clave ahí directo, para tenerla en un solo lugar: si la cambiás, la cambiás arriba y listo.

Para leer errores más adelante: si el sobre está mal, la carta ni se abre. Un error 401 significa "no te conozco" (revisá la clave). Un 400 significa "no te entiendo" (revisá el formato). Cuando te dé 401, no revises tu pregunta: revisá la API Key.
Ejecutás y no hay error. Si te aparece algo sobre comillas, revisá que no hayas borrado ninguna.
Paso 3 — La función

Esta es la pieza central. Recibe los mensajes, los manda, y devuelve lo que contestó la IA:

def consultar_ia(mensajes, nivel_creatividad): payload = { "model": "openai/gpt-oss-120b", "temperature": nivel_creatividad, "messages": mensajes } try: respuesta = requests.post(URL, headers=headers, json=payload) return respuesta.json()["choices"][0]["message"]["content"] except Exception as e: return f"Error: {e}"

Son pocas líneas pero pasan muchas cosas. Vamos una por una.

1. Los dos parámetros. mensajes es lo que le querés preguntar a la IA (más adelante va a ser el historial completo). nivel_creatividad es un número que vos elegís y que viaja como temperature.

2. El payload es el paquete que viaja. Es un diccionario con tres cosas, y cada una tiene su razón de ser:

  • "model" → qué modelo querés que responda. Groq ofrece varios, con distintos tamaños y velocidades. Si no lo aclarás, no sabe cuál usar.
  • "temperature" → cuánto se puede arriesgar el modelo. Va de 0 a 2, y si no la ponés, la API usa 1. Cerca de 0 elige casi siempre la palabra más probable: respuestas estables y predecibles. Más arriba se arriesga: respuestas variadas y creativas. Cerca de 2 se vuelve tan aleatoria que puede perder el hilo. Para un chatbot conversacional 0.7 anda bien; para sacar datos exactos de un texto conviene bajarla mucho.
  • "messages" → la conversación. Acá va lo que recibiste en el parámetro mensajes.

3. requests.post(...) es el viaje de ida. Ahí sale tu pedido a internet. Se usa post (y no get) porque le estás mandando datos, no solo pidiendo algo. Le pasás las tres cosas que necesita: adónde va (URL), el sobre (headers) y el contenido (json=payload). En esa línea tu programa se queda esperando hasta que el servidor conteste.

4. La línea de los corchetes desarma la respuesta. Acá está la parte que más confunde, así que vale la pena entenderla bien. El servidor no te devuelve el texto pelado: te devuelve un JSON con un montón de información alrededor, más o menos así:

{ "choices": [ <-- 1) ["choices"] entra acá { <-- 2) [0] es este primer elemento "message": { <-- 3) ["message"] entra acá "role": "assistant", "content": "Acá está lo que te contestó la IA" <-- 4) ["content"] } } ], "usage": { "total_tokens": 512 } }

Seguí los números del dibujo y vas a ver que son exactamente los corchetes de tu código, en el mismo orden:

respuesta.json()["choices"][0]["message"]["content"] 1 2 3 4

El [0] no aparece escrito en el JSON, y por eso confunde. Aparece porque después de "choices" viene un corchete [, y eso significa lista. Los elementos de una lista no tienen nombre: se piden por su número de posición. El primero es el 0.

Es una caja con cajas adentro. Para llegar al texto hay que ir abriendo una por una, y eso es exactamente lo que hace cada corchete:

  • respuesta.json() → convierte todo lo que llegó en un diccionario de Python.
  • ["choices"] → entra a la lista de respuestas. Se llama así porque la API está preparada para devolver varias versiones distintas de la misma pregunta.
  • [0] → agarra la primera de esa lista.
  • ["message"] → entra al mensaje.
  • ["content"] → y acá sí, el texto que buscabas.
¿Y por qué siempre [0]? ¿Nunca es [1]?
Con Groq, nunca. La lista existe porque la API permite pedir varias respuestas a la vez (con un parámetro llamado n), y ahí sí tendrías [0], [1], [2] para comparar. Pero Groq solo admite n = 1: siempre te devuelve una sola. Así que esa lista siempre tiene un elemento y el [0] nunca cambia.

Ojo, esto no significa que el número entre corchetes sea decorativo. Cuando trabajes con tus propias listas sí va a cambiar todo el tiempo: si guardás los datos de varios archivos en una lista, resultados[0] es el primero, resultados[1] el segundo, y así. Acá es fijo solo porque la respuesta viene de a una.

El return devuelve ese texto. Es importante que sea return y no print: con return el resultado queda guardado en una variable y lo podés seguir usando (agregarlo al historial, darle formato). Con print se muestra en pantalla y se pierde.

5. El try/except es la red de seguridad. Muchas cosas pueden salir mal en ese viaje: se corta internet, la clave está vencida, el servidor está caído. Sin el try, cualquiera de esas rompe el programa y se corta todo. Con él, Python intenta lo que está adentro del try, y si falla salta al except, que devuelve un mensaje contando qué pasó. Tu programa sigue vivo y vos te enterás del problema.

Lo importante: estas líneas son toda la conexión con la inteligencia artificial. Todo el resto de tu chatbot — el bucle, los comandos, el historial — es Python común y corriente. La IA entra por acá.
Ejecutás y no pasa nada visible. Definir una función no la ejecuta: eso viene en el paso siguiente.

Sesión 2 — Memoria y personalidad

🎯 Meta: que la IA recuerde la conversación y tenga un rol
Paso 1 — El historial y el system prompt

El historial es una lista donde se guarda toda la conversación. La IA lo lee completo cada vez: así "recuerda".

El primer mensaje del historial es especial: el system prompt, que define quién es la IA y cómo se comporta.

# Elegí el tema de tu chatbot y escribí sus reglas sistema = """Sos un asistente de recetas amigable y práctico. Solo hablás de cocina. Si te preguntan otra cosa, respondés que tu especialidad es la cocina. Tus respuestas son cortas y claras.""" historial = [{"role": "system", "content": sistema}]
Podés cambiar el tema: un asistente de deportes, de música, de videojuegos. Lo que quieras, pero escribí reglas claras.
Ejecutás y no hay error. Tu historial ahora tiene un elemento adentro.
Paso 2 — Un turno de conversación

Un turno son siempre estos tres movimientos, en este orden:

# 1. Guardar lo que dice la persona historial.append({"role": "user", "content": "¿Cómo hago una tortilla de papas?"}) # 2. Consultar a la IA mandándole TODO el historial respuesta = consultar_ia(historial, 0.7) # 3. Guardar lo que respondió la IA historial.append({"role": "assistant", "content": respuesta}) print(respuesta)
La IA te responde una receta, siguiendo las reglas que le pusiste en el system prompt.
Responde cualquier cosa, ignora las reglas: fijate que el system prompt esté en la posición 0 del historial y que le estés pasando historial a la función, no el mensaje suelto.
Paso 3 — Comprobá que recuerda

Esta es la prueba de que el historial funciona. Repetí el Paso 2 pero con una pregunta que dependa de lo anterior:

historial.append({"role": "user", "content": "¿Y cuánto tarda?"}) respuesta = consultar_ia(historial, 0.7) historial.append({"role": "assistant", "content": respuesta}) print(respuesta)
La IA entiende que "¿y cuánto tarda?" se refiere a la tortilla, aunque no la nombraste. Eso pasa porque le mandaste el historial completo.
Pregunta "¿cuánto tarda qué?": no estás acumulando en el historial. Revisá que uses historial.append(...) y no historial = [...], que lo pisa todo.

Sesión 3 — El chatbot completo

🎯 Meta: que funcione solo, en un bucle, hasta que quieras salir
Paso 1 — El bucle

Hasta ahora escribías las preguntas a mano en el código. Ahora el programa las pide solo, una y otra vez:

while True: mensaje = input("Vos: ").strip() if mensaje.lower() == "salir": print("¡Chau!") break historial.append({"role": "user", "content": mensaje}) respuesta = consultar_ia(historial, 0.7) historial.append({"role": "assistant", "content": respuesta}) print("IA:", respuesta)

while True se repite para siempre; el break es la única forma de cortarlo. El .strip() saca los espacios de más, y el .lower() hace que "Salir" o "SALIR" también funcionen.

Aparece el cuadro para escribir. Charlás con tu chatbot, y cuando escribís "salir", termina.
No para nunca: falta el break, o la comparación no coincide (fijate que tenga el .lower()).
Se cortó y quedó colgado: tocá el botón de detener de la celda y volvé a ejecutar.
Paso 2 — Un comando propio

Un comando es una palabra que el programa atiende sin mandársela a la IA. Agregá esto adentro del bucle, justo después del if de salir:

if mensaje.lower() == "/turnos": print(f"Mensajes en el historial: {len(historial)}") continue

El continue es clave: vuelve al principio del bucle sin gastar un turno con la IA. Sin él, el programa seguiría de largo y le mandaría "/turnos" a la IA como si fuera una pregunta.

Escribís /turnos y te dice cuántos mensajes hay, sin llamar a la IA.
Le manda "/turnos" a la IA igual: falta el continue, o el if quedó mal indentado (tiene que estar adentro del while).
Paso 3 — La prueba final

Antes de entregar, probá esto en orden:

  1. Entorno → Reiniciar y ejecutar todo.
  2. Hacé una pregunta de tu tema. Tiene que responder.
  3. Hacé una segunda pregunta que dependa de la primera. Tiene que entenderla.
  4. Preguntale algo fuera de su tema. Tiene que negarse, como dice el system prompt.
  5. Escribí /turnos. Tiene que responder sin llamar a la IA.
  6. Escribí salir. Tiene que terminar.
Los seis pasos funcionan sin errores, arrancando desde cero. Ahí está terminado. 🎉
